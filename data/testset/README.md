# 테스트 문서 세트 작성 가이드 (팀원용)

버전별(v0 → v1 → v2) 탐지 성능을 같은 기준으로 재기 위한 문서 모음입니다.

> **제출은 [SUBMIT.md](SUBMIT.md) 순서대로 GitHub에 직접 올려 주세요.**

## 규칙
- **모든 개인정보는 가짜로** 만듭니다. 실제 사람의 번호·주소를 쓰지 마세요.
- 문서는 `docs/` 폴더에 넣습니다. 형식은 `.txt`, `.docx`, `.pdf` 모두 가능합니다.
- 정답은 본인 정답 파일 `docs/labels_본인이름.json` 하나에 문서별로 모아 적습니다. (`labels.json`은 예시라 수정하지 않습니다)

## 정답(label) 형식
```json
{
  "file": "doc01_인사기록.txt",
  "note": "어떤 상황의 문서인지 한 줄",
  "entities": [
    {"category": "UNIQUE_ID", "type": "RRN",   "text": "900101-1234567"},
    {"category": "CONTACT",   "type": "PHONE", "text": "010-1234-5678"}
  ]
}
```
- `text`는 문서에 적힌 **글자 그대로** 적습니다(띄어쓰기·하이픈 포함).
- category / type 목록:

| category | type | 예시 |
|---|---|---|
| UNIQUE_ID | RRN (주민등록번호), FRN (외국인등록번호), PASSPORT, DRIVER | 900101-1234567 |
| FINANCIAL | CARD, ACCOUNT | 1234-5678-9012-3456 |
| CONTACT | PHONE, EMAIL | 010-1234-5678 |
| SENSITIVE | HEALTH, BELIEF, POLITICS, UNION 등 | "○○ 과장 당뇨로 입원" |

## 섞어 주면 좋은 것
- 표기 변형: `010 1234 5678`, `01012345678`, 주민번호 뒷자리 띄어쓰기
- **개인정보처럼 보이지만 아닌 것**: 회사 대표번호, 제품 일련번호, 날짜 (정답에 넣지 않음 → 오탐 측정용)
- 민감정보 문장(건강·사상 등): v1(LLM) 평가용
- 스캔 이미지 PDF·사진(PNG/JPG) 1~2개: 이제 **OCR로 읽으므로 정답(labels)도 일반 문서처럼 적어 주세요.** 인쇄 후 휴대폰으로 찍은 사진이면 더 좋습니다
- 일부러 알아보기 어려운 스캔(흐림·손글씨) 1개: "인식 신뢰도 낮음 → 차단" 확인용 (정답은 빈 목록, `note`에 의도 적기)

## 분량 목표
10\~20개 문서. 문서당 개인정보 0\~6개.
