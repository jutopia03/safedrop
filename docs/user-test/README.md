# 사용자 테스트 (담당: D)

코디세이 필수 요건 "최소 5명 이상의 실제 또는 잠재 사용자 테스트 → 피드백 반영"을 위한 폴더입니다.

## 일정
| 날짜 | 할 일 | 결과물 |
|---|---|---|
| ~11/4(수) 22:00 | 테스트 키트 PR | `시나리오.md`, `설문.md`(Google Form 링크 포함), `모집공지.md` |
| 11/5(목)~11/6(금) | 테스트 진행 (비대면) | Google Form 응답 |
| 11/6(금) 22:00 | 결과 PR + Issue | `결과요약.md` + 개선점마다 GitHub Issue 1개 |

## 올리는 방법
이 폴더(`docs/user-test/`)에서 `Add file → Upload files` → 파일 끌어다 놓기 → **Create a new branch** (`usertest-영문이름`) → `Propose changes` → `Create pull request`.
자세한 화면 순서는 [테스트 문서 제출 방법](../../data/testset/SUBMIT.md)과 같습니다.

## 참가자 설정 (시나리오에 그대로 사용)
- 서비스 주소: https://safedrop-7sx9.onrender.com/ (무료 서버라 첫 접속에 약 1분 걸릴 수 있음)
- 로그인: 직원 목록에서 **변시우 (영업팀)** 선택 + 시연 비밀번호
  - 비밀번호는 공지문·GitHub에 쓰지 않고, 참가 의사를 밝힌 사람에게만 개인 메시지로 전달
- 수신자로 쓸 직원:
  | 수신자 | 소속 | 유형 |
  |---|---|---|
  | 마도현 | 인사팀 | 개인정보취급자 |
  | 길하람 | 영업팀 | 같은 부서 |
  | 탁운재 | 개발팀 | 다른 부서 |
  | 봉태경 | 협력사 | 외부 |
- 화면 흐름: 파일 선택 → 수신자 체크(여러 명 가능) → **검사하기** → 수신자별 결과·설명 확인 → **허가된 대상에게 전송**

## 예상 결과 (운영자용 — 참가자에게 공개하지 않음)
발신자 변시우(영업팀) 기준.

| 파일 | 마도현 (인사·취급자) | 길하람 (같은 부서) | 탁운재 (다른 부서) | 봉태경 (협력사) |
|---|---|---|---|---|
| sample1 인사기록카드 | 원본 허용 | 마스킹본 (주민번호·계좌 가림) | 마스킹본 (주민번호·계좌 가림) | **차단** (3-3, 4-3) |
| sample2 주간회의록 | 원본 허용 | 마스킹본 (해당 문장 가림, 6-2) | **차단** (6-3) | **차단** (6-3) |
| sample3 스캔본 | 원본 허용 | 마스킹본 + 민감 문장 가림 | **차단** (민감정보 6-3) | **차단** |

- sample2·3의 민감정보(건강) 판단은 AI가 합니다. 예상과 다르게 나오면 그 자체가 중요한 결과이니 꼭 기록해 주세요.
- 연락처(휴대전화·이메일)는 사내 직원에게는 그대로, 협력사에게는 가려집니다(5-1, 5-2).

## 결과 정리 형식 (`결과요약.md`)
1. 참가자 수와 구성 (직장인 / 학생 / 보안·IT 경험 등 — 이름 없이)
2. 5점 척도 문항별 평균과 응답 수
3. 이해도 확인 문항 정답률 (예: "협력사에게는 어떤 결과였나요?")
4. 주관식 요약 (같은 의견은 묶고 언급 횟수 표시)
5. **개선점 목록** → 하나마다 GitHub Issue 등록 (`Issues → New issue`, 제목 `[사용자 테스트] 요약`, 본문에 근거 응답 인용). 팀장이 고친 커밋에서 Issue를 닫으면 "피드백 → 반영" 증빙이 됩니다.

설문 원본 응답(스프레드시트)은 올리지 않고 요약만 올립니다.
