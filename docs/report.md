# SafeDrop 결과보고서 (요약)

**팀 codev** (주시호·양원석·육민호·이태우·최시원) · 기업 PBL: 비상테크 「사내 P2P 파일 공유 서비스」
서비스 https://safedrop-7sx9.onrender.com/ · 저장소 https://github.com/jutopia03/safedrop

> 파일을 보내기 직전, 파일 속 개인정보·민감정보를 찾고 **받는 사람마다 허용·마스킹·차단**을 판단해 사내 규정 조항으로 설명한 뒤, 허가된 파일만 서버 서명 토큰과 함께 브라우저 간(P2P)으로 보내는 사내 전송 채널.

---

## 1. 기획 — 무엇을, 왜
**문제.** 국내 개인정보 유출 신고 중 **업무 과실이 25~30%**(2024년 91건, 2025년 110건)이고, 대부분 단체방 게시·이메일 동보 발송·잘못 첨부처럼 *"이 파일을 이 사람에게 보내도 되는가"를 묻지 않아서* 생겼다(개인정보보호위원회·KISA). 같은 파일도 받는 사람에 따라 허용 범위가 다르고(인사팀은 원본, 다른 부서는 가린 사본, 협력사는 금지), "○○ 과장 공황장애 진단" 같은 **문장 속 민감정보**는 번호 형식 기반 도구로 잡히지 않는다. 근거·출처: [요구사항 1장](requirements.md)

**접근.** 개인정보를 *찾는* 방식은 상용 DLP에서 검증된 방식(형식 + 검증식 + 주변 문맥)과 같은 계열로 직접 구현하고, 새로 설계한 것은 **찾은 다음**이다.
- 같은 파일을 **수신자마다** 원본 / 가린 사본 / 차단으로 나눈다
- 판정 근거를 **사내 규정 조항**으로 설명하고, 차단 시 **원문에서 고칠 위치**를 보여 준다
- 전송 채널 자체를 제공하고, **받는 쪽 브라우저가 서버 서명을 검증**한다 (화면 조작·파일 바꿔치기 방지)

**원 기획 대비 바꾼 점과 이유**
| 기업 과제 원문 | 결과 | 이유 |
|---|---|---|
| 허용·마스킹·차단을 판단하는 AI Agent | 판정은 **규칙표**, AI는 문맥 판단과 설명 | 보안 판정은 같은 입력에 같은 결과가 나오고 감사할 수 있어야 함 |
| 브라우저 기반 P2P 전송 | P2P + 실패 시 10분 메모리 중계(1회 수신 후 삭제) | 수신자 미접속·사내망 제약으로 P2P가 실패할 수 있음 |
| (언급 없음) | 서명 토큰, OCR(스캔 PDF·사진) | 위변조 방지 / 멘토·퍼실리테이터 질문 반영 |
| 외부 클라우드 사용 불가 기업 | 시연 서버는 외부 AI(코디세이 API) 사용, **로컬 LLM 구성 측정 + 사내 설치 묶음** 준비 | 개발·시연 환경 제약. 대상 기업 조건은 로컬 구성으로 충족 ([local_llm](eval/local_llm.md)) |

## 2. AI 적용 방식 — AI에게 결정을 맡기지 않는다
```
업로드 → 텍스트 추출(스캔은 OCR) → ① 정규식+문맥 탐지 ─┐
                                → ② AI 문맥 판단(후보 문장만) ─┴→ ③ 규칙표 판정(정보 유형 × 수신자 유형 → 조치+조항)
→ ④ 조항 검색(RAG) + AI 설명 → 코드로 인용 검증 → ⑤ 서명 토큰 → P2P 전송 → 수신 브라우저 검증
```
- **AI가 맡는 일은 두 가지뿐:** 정규식이 원리적으로 못 잡는 문장 속 민감정보 판단(정규식 재현율 0%), 규정 근거를 사람이 읽을 문장으로 설명.
- **AI 출력은 코드가 검증:** 판단 근거 문구가 원문에 실제로 있는지 대조, 설명은 검색된 조항만 인용·실제 조치 언급·200자 이내 등 5가지 검사. 실패하거나 프롬프트 인젝션이 의심되면 **차단 쪽으로 처리(fail-closed)**하고 템플릿 설명으로 대체한다.
- **비용·속도:** 후보 문장만 AI에 보내 문서당 호출 1회, 판단 모델과 설명 모델을 분리해 설명 대기 35초 → 2.4초.

## 3. 기술 결정과 근거
측정으로 고른 것과 조건·논리로 고른 것을 구분해 적는다.

| 결정 | 선택 | 근거 | 측정 |
|---|---|---|---|
| 정형 탐지 | 정규식 + 문맥(표 머리글·키워드, 공용 메일·법인카드 제외) | 정밀도 69% → 96% | ✅ |
| 문장 판단 | LLM, 후보 = 주제어 또는 특정인 언급 문장 | 재현율 0% → 100% | ✅ |
| 조항 검색 | BM25(글자 2-gram) + 조 제목 필터 | Recall@3 90% → 100% (임베딩과는 비교 안 함) | ✅ |
| 모델 | 판단·설명 분리 / 로컬은 qwen3:8b + exaone3.5:7.8b | 대기 35초 → 2.4초 / 3개 모델 비교, 14b가 더 나쁨 | ✅ |
| OCR | Tesseract 5 + 전처리(중앙값 필터·Otsu·psm 6) | 폐쇄망·무료·CPU 조건. 클라우드 OCR은 외부 전송, 딥러닝 OCR은 GPU 필요. 전처리로 개인정보 인식 3~4/6 → 6/6 | 전처리만 ✅ |
| 서명 | ECDSA P-256 | 브라우저(WebCrypto)가 공개키로 검증 가능. HMAC은 브라우저에 비밀키가 필요 | 논리 |
| 서버·화면 | FastAPI / 프레임워크 없는 HTML·JS | 문서·AI 라이브러리가 Python에 많음 / WebRTC·WebCrypto가 브라우저 기본 기능 | 논리 |

**예외 처리:** 읽을 수 없는 파일·미지원 형식·OCR 신뢰도 60% 미만은 '확인 불가 → 전 수신자 차단'(규정 7-1), AI 장애 시 보수 판정, WebSocket 자동 재연결, 업로드 10MB·로그인 실패 제한. 자동 테스트 63개(AI·네트워크 없이 약 10초). 상세: [아키텍처](architecture.md), [개발 과정 S1~S13](understanding.md)

## 4. 결과와 검증
테스트 데이터는 **개발자가 아닌 팀원**이 만들었다(만든 사람이 자기가 예상한 경우만 확인하는 일을 막기 위해).

| 항목 | 베이스라인 | 최종 |
|---|---|---|
| 정형 개인정보 탐지 (문서 28개, 정답 76개) | 우리 v0: 재현율 87% · 정밀도 69% | **95% · 96%** |
| ↳ 개선에 쓰지 않은 문서만 (과적합 점검) | 정밀도 58% | **94%** |
| 문장 속 민감정보 (20문장, 경계 사례 포함) | 정규식만 재현율 0% | **100%** (정밀도 86%, 오류 2건 모두 경계 사례) |
| 근거 조항 검색 (20개 상황) | Recall@3 90% | **100%** |
| AI 설명 인용 검증 (20개 상황) | 프롬프트 보완 후 25%로 악화 | 원인 분석·수정 후 **20/20** |
| 폐쇄망(로컬 LLM, RTX 4080 SUPER 16GB) | — | 판단 90%(외부 API와 같음), 설명 18~20/20, GPU 약 11GB |

**사용자 테스트 (팀원 제외 5명, 직장인 2·학생 3):** 판단 납득 4.8 · 근거 설명 4.6 · 사용 편의 4.8 · 마스킹본으로 업무 가능 4.8 · 사용 의향 4.6 (5점 척도). "협력사에게는 어떤 결과가 나왔나" 이해도 확인 **5/5 정답**. 피드백 2건을 4가지 기준(실제 사용 문제인가·인원·서비스 목적·비용)으로 판단해 반영: ① 차단 원인 위치 보기 ② 중계 전송을 '실패'로 오인하게 하던 문구 수정 (Issue #7, #8). [결과 요약](user-test/결과요약.md)

## 5. 실용 가능성
**도입에 필요한 것이 적다.**
- **사람:** 직원 1명당 이름·부서·개인정보취급자 여부·외부인 여부 4가지만 등록하면 수신자 유형이 자동으로 정해진다. 사람마다 규칙을 만들지 않으며, 규칙은 *정보 유형 5 × 수신자 유형 4 = 20칸* 표 하나다.
- **규정:** 조항 번호(`[3-1]` 등)를 붙인 텍스트 문서 + 20칸 규칙표. 검색 색인은 서버 시작 시 자동 생성되고 AI 추가 학습은 필요 없다. 회사가 바뀌어도 **코드 수정 없이** 규정·규칙표만 교체한다.
- **환경:** 외부 API 없이 16GB GPU 1대 사내 서버로 동작하는 설치 묶음(`deploy/onprem/`, docker-compose).
- **지원 형식:** TXT, DOCX(표 포함), PDF, 스캔 PDF·PNG·JPG(OCR). 그 밖의 형식은 차단.

**만약 실제로 도입한다면** 먼저 필요한 것: 사내 계정(SSO/LDAP)·조직도 연동, 차단 시 예외 승인 흐름, 한글(HWPX)·엑셀 지원, 실제 업무 문서 수백 건 규모 재검증. 이후 전사 확대(여러 서버·종단 간 암호화·원본 형식 마스킹)와 메일·메신저 연동 순. 서비스화한다면 사내 설치형 라이선스(금융·공공·의료)와 회사별 규정 맞춤 구성을 상정한다. [아키텍처 6장](architecture.md)

## 7. 한계 (정직하게)
- 테스트 데이터가 수십 건 규모라 일반화에 한계가 있다. 이름·주소 단독은 탐지하지 않는다.
- OCR 엔진은 다른 엔진과 비교 측정하지 않았고(조건으로 선택), 남은 탐지 오류의 절반 이상이 OCR 오인식이다.
- 마스킹본은 .txt로 나간다. 사용자 테스트는 5명·비대면이고, 반영 후 버전은 다시 테스트하지 않았다.
- 사내 설치 묶음은 설정·의존성 검증까지 했고, GPU 서버에서 묶음 전체 실행은 하지 않았다(모델 측정은 별도로 실시).

*모든 조직·규정·개인정보는 시연용 가짜 데이터입니다.*
